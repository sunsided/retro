§Triple Buffering Crate

This crate provides a utility for implementing triple buffering or more generalized multi-buffering patterns. It includes the TripleBuffer type alias built on top of the generic MultiBuffer struct, allowing developers to create and manage buffers designed for concurrent or time-sensitive workloads.

The primary purpose of this crate is to enable safe, lock-free access to the latest data in one buffer while allowing modifications in other buffers. This pattern is commonly used in applications like video processing, gaming, or other scenarios that demand a balance of performance and data synchronization.

§Main Features

  • TripleBuffer<T>: A convenience alias for three buffers (standard triple buffering).
  • Generic Multi-buffering: MultiBuffer<T, SIZE> supports any number of buffers via constant generics.
  • Lock-free concurrency: Ensures safe access without blocking threads.
  • Convenience methods for buffer access, mutation, and updating the latest pointer.

§Examples

§TripleBuffer Example

The following example demonstrates how to use a TripleBuffer:

use multibuffer::TripleBuffer;

fn main() {
    // Create a TripleBuffer with an initial value of 0.
    let buffer = TripleBuffer::new(|| 0);

    // Modify a specific buffer (index 1).
    *buffer.get_mut(1) = 42;

    // Publish the updated buffer (index 1).
    buffer.publish(1);

    // Access the latest published buffer.
    assert_eq!(*buffer.get_latest(), 42);
     
    // Further modifications and publishing.
    *buffer.get_mut(2) = 100;
    buffer.publish(2);
    assert_eq!(*buffer.get_latest(), 100);
}

§Implementation Details

  • The MultiBuffer struct stores an internal array of buffers, fence markers, and exposes methods for interaction. Buffers are allocated using UnsafeCell for efficient mutable access without synchronization primitives.
  • The Sync implementation leverages careful safety design to allow multi-threaded use while adhering to Rust’s safety guarantees. The buffers must not be simultaneously accessed in unsafe ways outside the provided API.

§Notes

  • The correctness of this implementation depends on the user following the API’s safety rules—get_latest and get_mut methods should never be misused concurrently in order to prevent undefined behavior.
  • As of now, the crate relies on constant generics (const SIZE: usize) for specifying buffer sizes, which requires a fixed buffer count at compile-time.
